# 语义基线发现

把当前源码、机器契约、测试和正式设计整理成一套可追踪的项目语义事实。没有明确任务时覆盖 Baseline 覆盖的已完成代码；
有明确任务时只读取 `semantic-preflight` 的允许路径。

## 预检

1. 调用 `semantic-contract` 取得对象合同和校验命令。
2. 读取项目指令、当前 Git 状态、已有 `.echo-semantic/`、design 和 ADR。
3. 搜索用户入口、后台入口、状态权威、持久化、外部副作用、失败恢复、公共契约和语义资产。
4. 分类全部 Git 路径；生成代码、第三方代码和排除路径仍必须有明确分类与复查条件。

## 建模

1. 先建立候选事实底账，再按独立触发、状态权威、生命周期、副作用和裁决条件划分边界。
2. 每个中高风险能力建立 Capability Map，展开入口、结果、数据流、策略来源、失败路径和场景清单。
3. 为文件、符号、入口、状态权威、协议、测试消费者和文档建立 `asset` 对象；候选重复只记录线索。
4. Behavior 保存重要行为承诺，Rule 保存不变量和唯一权威，Evidence 只保存可复用证据。
5. 未知事实保持 `needs_review`，不得为了闭合而伪造行为或绝对安全结论。

需要独立探索时派发 `semantic-boundary-explorer`；需要能力闭合复核时派发
`semantic-capability-reviewer`。宿主没有专用角色时使用只读探索或审查能力，并传入完整路径、revision、范围和输出合同。

## 完成条件

- 当前源码摘要一致；
- 所有路径已分类且不存在冲突；
- 所有当前源码引用可以解析；历史引用能在对应 Git tree 中解析；
- 资产身份稳定，候选簇可追溯到源码和消费者；
- 库存闭合与行为模型闭合分别给出真实状态；
- 结构校验和严格快照校验通过。

完成后调用 `semantic-verify`。本 Skill 不修改业务代码。
