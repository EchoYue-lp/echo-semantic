# 生成前语义预检

在写代码前证明为什么改、复用什么、由谁继续拥有语义，以及怎样验证。预检是任务内工作合同，不是长期架构库。

## 输入

- 目标仓库根目录和生效的项目指令；
- 用户目标、授权范围和现有设计或计划；
- 当前分支、提交标识、未提交状态；
- 可选的现有 `.echo-semantic/` 基线。

## 预检

0. 首次发现会话开始前已有未提交差异时，先盘点暂存、未暂存、未跟踪路径及验证依据，在第一轮主动询问用户处置策略，不把未提交直接称为缺陷。可选策略是接管指定差异、保留已有差异仅处理本轮范围、暂停修改仅只读。未答复或无法绑定可信观察时只允许只读，不得修改或交付，不自动选择默认策略。
1. 将变更归为 `bugfix`、`feature`、`refactor`、`contract` 或 `style`。
2. 标记公共 API、状态权威、协议、跨服务迁移、持久化、并发/恢复、外部副作用和未知证据风险。
3. 先读取已有 Capability Map、直接目标实现、直接调用方和相关测试，按名称、概念及真实调用路径做有界搜索；发现跨边界、未知生产入口或复用依据不足时逐步扩大，不把完整仓库调查作为每个任务的默认步骤。区分定义、注册、生产可达和已验证。
4. 列出应复用的 Capability、Rule、公共接口、实现、测试和文档。
5. 判断通用机制、产品策略和适配边界，确认唯一状态权威；能扩展时禁止平行存储、状态机、协议或近义术语。
6. 给出允许修改路径、明确不触碰路径、旧路径退出目标和最小充分验证矩阵。

## 复用决定与内容依据

有无语义基线都可以开展任务，不先全量建库。优先直接复用，其次扩展已有实现；新增要说明候选不适用或没有找到合适候选的理由。名称或文本相似不能替代输入输出、状态归属、权限、副作用和失败处理的比较。

记录使用 schemaVersion: 2。用 `--search` 保存已实际搜索的范围，`--reuse-decision reuse|extend|new` 保存决定，`--reuse` 保存理由。候选用 `--candidate` 传入含 `path`、`symbol`、`selected`、`reason` 的 JSON 对象；复用或扩展必须选定至少一个候选。`--evidence <路径>` 固定相关内容摘要；`--mutable-evidence <允许修改路径>` 表示该依据随任务变化，完成时读取当前内容，不把编辑前摘要当作完成证据。候选路径自动纳入依据。

语义对象引用按合同文件名直接定位并绑定依据，不扫描无关材料。需要读写的现有语义对象应显式声明为 mutable evidence。旧自由文本记录需要重建，不自动补造调查事实。Hook 核对合同和依据，不能证明搜索完整或语义决定正确。

## 调查深度与停止条件

- 局部、可逆且证据明确的修改：确认目标行为、现有 owner、允许路径和一项最低充分验证后停止调查，直接编码。不要求完整仓库盘点、额外架构报告或重复正式设计。
- 涉及多个调用方但不改变公共契约或关键状态：调查相关边界及直接消费者，补充组合验证；发现新的未知区再扩大。
- 公共 API、状态权威、协议、持久化、并发恢复、权限、外部副作用、删除或未知生产证据：升级调查与验证深度，保留适用的架构权威和语义依据，不走局部捷径。
- 文件后缀、目录名和文件数量只能作为线索；规则文档、安全测试、配置和治理脚本也可能影响高风险行为。路由名称不能替代实际风险判断。
- 搜索结果足以回答复用、owner、影响范围和验证方式时停止；只为当前未知问题追加证据，不反复生成同一份长报告。

## 任务内增量预检

任务需要保存日志、完整运行结果、临时脚本、候选补丁、源码副本或中间清单时，先运行插件 `scripts/artifacts.mjs prepare --root <仓库绝对路径> --task-id <安全任务标识>`，统一写到返回的 `.echo-semantic/local/<task-id>/`；任务标识为至多 128 字符的安全字母、数字、点、下划线或短横线目录名。CI 沿用其 Artifact。目录准备失败时先处理原因，不降级写入 docs。`allowedPaths` 只授权修改，不表示这些路径都应暂存或提交。

本地产物只是调查线索，不能作为正式 `code_refs`、`source_refs` 或复用实现候选。正式复用依据引用当前源码和测试；已执行验证的原件位置与限制记录在相关 Evidence 正文，不复制整套原件。清理和历史重写分别遵守用户授权。

- 一个任务建立一次工作合同；同一任务内无需为每次编辑、每轮对话或修复同一测试失败重复完整调查。助手记录已确认事实和剩余未知，不把缓存当作源码证据。
- 复用前必须确认目标、授权和风险不变，并用原任务标识检查当前记录与实际写入路径：

```bash
python3 scripts/preflight.py check --root <仓库绝对路径> --task-id <原任务标识> \
  --path <本次修改路径> --compact
```

- `check` 重新检查仓库、HEAD、有效期、语义引用和 design/ADR 内容，不写入、不延长记录有效期。通过不代表工程验证已完成，也不证明助手保存的调查事实仍然成立。
- 新任务不继承旧任务授权。目标、授权、边界、复用依据或风险变化，新增范围、HEAD 或设计权威变化时，对变化的影响闭包补充调查并重新 `record`；同一任务的风险与高风险信号只能升级，不能借增量预检降级。
- 已有差异处置按会话复用用户明确策略；事实不变时不重复询问，受保护差异或 HEAD 变化时重新询问，不省略受保护内容校验。
- 中间使用针对性工程验证，相邻编辑形成一个行为后统一运行；交付前仍执行仓库要求的完整验证，最后一次相关修改会使旧验证证据失效。

## 已有差异处置

- 使用插件的 `scripts/session-changes.mjs inspect --root <仓库绝对路径> --session-id <宿主会话标识>` 读取盘点与当前策略，不能按任务 id 猜测会话标识。
- 不得只说“存在已有差异”。首次提问正文先展示 `presentation` 中的仓库根、暂存/未暂存/未跟踪计数、具体路径与状态；嵌套仓库还要展示父仓索引 revision、当前 HEAD、分支和内部差异摘要。路径超过展示上限时按顶层范围归组并说明省略数量，但所有与当前任务重叠的路径必须逐项列出。不展示完整文件内容或敏感日志。
- 将盘点与当前任务目标、当前 Git 根/worktree 和预检允许路径比较，明确说明每组差异与当前任务是重叠、独立还是无法判断。不得用“看起来无关”代替仓库根、路径或调用范围证据。
- 在三个策略中给出一个唯一推荐和事实理由：全部差异与本轮范围独立时推荐 `preserve`；必须修改其中明确路径时推荐只 `adopt` 这些路径并保护其余差异；任务范围、差异来源或观察可信度无法判断时推荐暂停修改仅只读（`readonly`）。推荐不能代替用户明确答复。
- 在询问前保存 inspect 返回的 `questionFingerprint`；用户明确回答后才调用 `decide`，以该指纹为 `--fingerprint`，携带 `--strategy adopt|preserve|readonly` 和简短脱敏的 `--basis <用户明确答复依据>`；接管时为每个选定初始差异提供 `--path <仓库相对路径>`。
- 当前观察与 `questionFingerprint` 不一致时，先调用 `refresh --root <仓库绝对路径> --session-id <宿主会话标识>` 刷新待裁决盘点，再重新询问；不能用重新计算的指纹套用用户对旧盘点的答复。
- 普通预检不能代替裁决。保留策略不得修改已有差异路径；接管只解除选定路径保护，仍须预检和完成验证；只读策略不得修改或交付。
- 已询问但未答复时不重复催问，允许结束只读会话并保留待裁决状态。HEAD 或受保护差异变化后重新盘点询问；恢复时不自动把未结算修改重新归为初始差异。
- 裁决不表示差异已验证，不授权提交、暂存、丢弃、清理或发布。已有有效验证收据可作为询问的依据，但不能代替用户策略。
- 以上助手流程不是机器门禁；Hook 只在真实宿主能观察到的写入和停止路径执行确定性检查，CI 仍独立检查最终差异。

## 架构门禁

新的公共 API、状态权威、协议、跨服务迁移或关键架构变化必须先读取
[架构收敛工作流](workflows/architecture-convergence.md)。先发现并绑定已有 design/ADR；只有没有现有权威时才创建新的
正式设计。`semantic-decide` 只用于证据无法确定的产品选择和风险接受。

## 机器记录

分析完成后，在本 Skill 根目录运行：

```bash
python3 scripts/preflight.py record --root <仓库绝对路径> --kind <分类> --risk <风险> \
  --allow <允许路径> --search <已搜索范围> --reuse-decision reuse|extend|new \
  --reuse <复用或新增理由> --verify <验证命令> \
  --reuse-existing-boundary <边界复用理由>
```

Windows 使用 `py -3 scripts/preflight.py ...`，参数合同不变。

record 复用插件已要求的 Node 20+ 运行态模块，在同一 repo-local 锁内重读旧记录、比较风险并原子写入；check 仍只需 Python 和 Git。锁竞争有界失败，不绕过锁或降级覆盖。

高风险参数按实际情况增加：

- `--public-api`、`--new-state-authority`、`--new-protocol`、`--cross-service-migration`；
- `--architecture-change`、`--unknown-production-code`；
- `--basis <依据>` 和 `--semantic-ref <语义对象>`；
- `--design-authority <现有或新设计路径>`、`--adr <ADR 路径>`。
- 新增边界时用 `--new-boundary-reason <理由>` 替换 `--reuse-existing-boundary`。
- 受控删除增加 `--repair-ref <Finding>` 和 `--delete-path <仓库相对路径>`；删除路径必须属于已批准的 repair Finding。

记录写入目标仓库 `.echo-semantic/preflight.json`，并自动加入 `.git/info/exclude`，不进入版本控制。脚本自动生成任务标识并写入 `scope: task`；若宿主事件提供
任务 id，应使用 `--task-id` 写入同一标识。新任务启动且无需保留已有差异依据时消费旧记录；待裁决只读 Stop 保留依据，不表示验证通过。无待结算变化或成功验证后的 Stop 消费记录，失败 Stop 保留以便修复后重试。记录只供当前任务的 Hook 和校验器检查允许路径、新鲜度与高风险依据。

完成验证默认 `verificationScope: task`，旧记录缺省同义。用户明确需要 Baseline 更新或全项目完成验证时，record 增加 `--verification-scope repository`。该声明只选择完成校验深度，不扩大允许写入范围、不触发自动建库或扫描。后续必须执行匹配范围的真实校验；Stop 从有效预检选择 `--task-scope` 或 `--repository-scope`，范围错配、严格快照失效或保护差异变化均失败。只手动运行全项目命令不能替代绑定任务和当前工作树的 Stop 收据。

## 衔接

1. 普通局部改动通过预检后直接编码。
2. 首个代码差异形成后调用 `semantic-diff`，风险深度只能升级。
3. 高风险失效、残余风险或事故关联进入 `semantic-audit`。
4. 完成工程工具验证后调用 `semantic-verify`。

删除或替换旧实现时调用 `semantic-repair`，先记录替换关系、回滚点和行为等价证据，再执行 Delete 工具。
