# 本地产物与长期证据的提交边界

## 确认依据

2026-10-15 用户认可“本地产物统一存放、Git 保留必要长期材料”，并要求创建 goal 完成方案。调查发现 SDK 提交 `79b91e3` 将 25 个诊断归档文件纳入 Git；问题来自助手扩大归档范围，而非插件正常路径自动执行提交。本设计只落实项目无关的插件机制；SDK 存量迁移需针对其当前引用与活跃任务另行执行，不在本轮改写该仓库。

## 问题与目标

真实验证需要可核查依据，但不要求每轮日志、完整结果、临时脚本、候选补丁、源码副本与中间清单永久进入 Git。目标是明确产物去向、保留验证强度、减少重复归档，并由确定性检查发现明确不可提交的产物。

## 范围与非目标

覆盖 `.echo-semantic/local/<task-id>/` 的准备和本地忽略、扫描与快照隔离、提交检查、分发检查、Skill 规则和验证。既有七个运行态文件保持位置和合同。无新增数据库、调度器、后台进程、隐藏遥测、宿主事件或证据状态库；不自动提交、安装 Git Hook、清理本地产物或重写历史。

## 目标行为

所有任务本地产物默认写入同一个任务目录，不强制按日志和临时文件分类；重复执行需要时可增加运行子目录。目录准备复用运行态的 `.git/info/exclude` 能力；忽略设置失败、路径为符号链接或目标已被 Git 跟踪时明确失败，不能降级写到 docs。任务标识只作为一个安全路径段，不能越出目标目录。

只有修复和关闭 Finding、证明重要行为与公共契约、记录长期维护限制时才维护长期 Evidence；优先更新已有相关 Evidence，不按命令次数新增材料。执行证据保留对象、源码版本或内容身份、命令、必要环境、真实退出状态、结论、限制和产物定位。机器检查不证明命令执行真实性、检索充分或结论正确。

本地引用明确仅当前工作区可用；CI 引用具体运行及 Artifact。摘要只用于身份核对，不能替代原件。原件不可获取时如实说明限制；需要新证明时重新验证。长期源码引用使用现有 Git revision 与路径，避免复制旧源码和候选源码。临时反例只有整理成正式回归测试或必要精简 fixture 才进入 Git；不按扩展名禁止正常 JSON、XML、日志格式 fixture。

本地产物从语义对象枚举、源码盘点和源码摘要中排除，即使用户强制暂存也不得读取它来建立正式语义事实；强制暂存或提交由独立检查明确报错。源码引用与复用依据不能将 local 内容提升为长期源码权威。

## 核心结构与数据流方案

`runtime/project-state.mjs` 继续拥有本地排除与安全目录准备。任务使用轻量命令取得 local 目录，普通工具将产物写到该目录；插件不接管测试执行器。长期材料仍使用现有 Evidence 合同，不引入每次运行一个 manifest 的要求。

统一产物检查支持暂存区和相对 Git 基准的候选提交。暂存检查读取索引文件身份，CI 检查读取候选 Git tree，不能用工作区覆盖后的内容替代待交付版本。运行态与 local 路径属于确定禁止项；疑似原始产物仅给出带路径的提示，不把启发式分类伪装为精确门禁。项目已有明确规则仍独立生效。本轮不新增可执行配置或通用例外数据库。

删除不可提交文件的清理变化允许通过。历史已有归档不因升级全部阻断；本轮不批量分类旧 docs。现有完整语义验证仍拒绝跟踪运行态，任务检查与 CI 独立核对当前交付变化，避免缺少基线时漏检。

分发包不得包含 local 内容；打包和宿主安装复用同一打包结果。`allowedPaths` 只授权修改，不决定哪些文件值得提交。Skill 是行为指引，真实检查由校验器和 CI 执行，宿主 Hook 的实际运行证据单独报告。

## 异常与边界场景

- 正常任务生成本地产物不改变 Git 待提交文件和严格源码摘要。
- `git add -f` 强制加入 local 或运行态时暂存检查失败；工作区改成普通内容不能掩盖索引中的违规路径。
- 提交路径包含空格、换行或中文时按 Git NUL 分隔处理，不拼接 shell 命令。
- 纯删除违规文件可通过；重命名到违规位置必须失败。
- 原始日志放到 docs 等其他位置只形成疑似产物提示；该检查不能保证识别任意命名的原始产物。
- 合法 fixture、正式测试与现有语义对象正常通过，不以文件数量或后缀推断错误。
- local 或任务目录为符号链接、任务路径逃逸、已有跟踪冲突、忽略无法生效时失败，不覆盖现有数据。
- 本地产物包含错误或敏感内容时不由插件主动采集、打印或上传；检查只列路径和规则。
- 多工作树分别使用当前 Git 根和对应排除文件；不把另一个工作树的本地目录作为权威。

## 关键取舍与复用约束

使用项目内单一本地目录便于 Agent 明确输出位置，沿用现有 Git 排除，不增加新的项目外存储。保留现有运行态避免无关迁移。Git、Node/Python 标准库和既有打包、扫描、语义校验足以实现，无新依赖。确定规则阻断、疑似产物提示，在防止插件产物误提交和避免伤及 fixture 之间保持边界。

存量治理必须先核对引用、保存可恢复归档，再更新引用和删除副本。普通清理提交不会减少历史体积；历史重写另行授权。默认不自动删除，也不硬编码保留期限。

## 验收标准

1. 正常准备及生成任务产物后 Git 状态不增加产物路径；非法目录和标识失败。
2. local 内容变化不影响源码摘要；盘点不读取或建模 local，正式源码引用不能指向 local。
3. 强制暂存、候选提交中的 local/运行态被发现；删除、合法 fixture、特殊字符文件名和无基线项目有回归覆盖。
4. 分发包排除 local；打包检查能发现泄漏，现有宿主投影与 manifest 校验继续通过。
5. Skill、命令文档和项目规则一致，不要求整套原始归档，不新增自动清理和提交行为。
6. 执行 `npm test`、`npm run verify` 和任务范围 semantic-verify；报告已有差异处置、验证范围及真实宿主验收限制。

## 显式全项目 Stop 结算补充设计

2026-10-15 真实 Stop 暴露既有流程缺口：Hook 固定调用 task 入口，而该入口拒绝 Baseline 更新，手动全项目通过也不能结算。用户已明确接管 Stop 相关路径并授权修复。

复用 schemaVersion: 2 的现有预检，新增可选 `verificationScope: task|repository`，缺省按 task 兼容旧记录。CLI 通过 `--verification-scope repository` 显式声明全项目完成验证；它不扩大 allowedPaths、不替代差异裁决、不自动建库，也不让普通任务或基线变化自动升级为全项目扫描。

Stop 从有效预检选择任务或全项目完成入口。二者均核对任务、HEAD、允许路径、保护差异及同次高风险依据；repository 入口额外运行真实全项目严格结构、引用与快照检查。全项目入口必须与预检声明一致，不能由 CLI 标志将 task 记录提升为 repository 成功。

全项目报告保持绑定当前 taskId，明确 `scope: repository`，绑定全仓源码身份和正式语义材料内容；成功收据同时绑定实际验证范围、任务、HEAD、工作树、插件和宿主身份。任何失败不生成成功收据、不消费预检。成功后按既有生命周期消费预检并允许同一快照重入；收据复用不能放过内容变化、待结算记录或新的任务。全项目机器检查不表示行为模型闭合，继续报告 globalClosure: not_checked。

repository 收据通过 `repositoryContentDigest` 绑定正式目录集合、README、`.gitkeep`、材料原件、实际源码引用和原任务依据（含被 Git 忽略的依据）。重入重新运行严格校验并比较内容身份；瞬时文件/目录观察返回 Hook，结算前核对，避免忽略内容在校验返回后变化却被接受。这些瞬时观察不写入长期材料或收据。task 收据保持原轻量路径。

复用现有项目状态锁：JSON 运行态写入参与同一锁，已持锁调用不重复获取。Stop 不在耗时验证期间持锁；启动前固定预检、继续包和当前会话裁决身份，验证后在锁内比较同一身份、核对内容观察、发布收据并只消费这次记录。另一任务或继续包在验证期间写入时，旧 Stop 拒绝结算并保留新记录。重入也在锁内核对工作树与待结算记录，不能因收据仍匹配起点就忽略验证期间的变化。

没有 Baseline 的显式全项目请求失败并保留缺口，不自动创建材料。源码 Hook 的夹具执行、已安装副本更新和 GUI/新会话验收分别报告；不手动填写收据，也不直接改写宿主缓存。新增回归覆盖默认局部仍拒绝 Baseline、显式全项目成功、范围错配、过期摘要、范围外变化、内容变化后旧收据失效及失败不消费记录。
