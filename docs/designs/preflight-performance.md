# Preflight 性能优化设计

## 目标

减少首次编码前的无关调查与同一任务的重复取证，降低逐编辑 Hook 的全量内容读取；保留原有权限、语义依据、既有差异裁决及最终验证约束。执行依据为用户对四项优化的明确确认。

## 当前适用范围

日常任务入口和最终语义验证范围由 `docs/supreme/specs/task-scoped-reuse-governance/design.md` 收敛。本文历史方案中的全项目 Stop 校验只适用于显式全项目治理；日常 Stop 使用当前任务验证。工作区差异保护、锁内检查、风险升级与工程检查继续适用。

## 范围与边界

仅优化 semantic-preflight、预检 CLI、编辑准入、宿主探测及语义引用读取。Skill 继续是流程唯一真理源；Hook 与校验器继续执行确定性约束。没有数据库、常驻服务、新宿主事件或隐藏遥测。已有未提交优化在当前工作区保留；本轮不提交、安装、发布或声称真实宿主验收。

## 方案与失效规则

- 调查从已有地图、目标实现和直接消费者开始；未知生产证据及公共契约、状态、权限等高风险变化升级。目录和后缀不直接决定低风险，事实齐全后停止调查。
- 同一任务优先 check，绑定原 taskId 与写入路径，重新核对 root、HEAD、24 小时有效期、语义引用和设计内容摘要；不延长有效期。任务目标、授权、范围和调查依据的变化由助手补充调查后 record。同一 taskId 的风险和高风险信号不得降级，新任务不能使用旧任务记录。
- record 复用已要求的 Node 20+ 运行态模块，旧记录重读、风险比较和原子写入由同一个 repo-local 锁串行保护；锁竞争有界失败，取得锁后重读最新状态，不引入第二套锁或持久状态。check 仍只使用 Python 和 Git。
- 锁内通过调用方的 Python 解释器执行同一个完整 preflight_contract，不使用 Hook 准入子集代替提交合同；包括 repair Finding 的存在性、已完成状态、删除风险及删除/替换/回滚字段。等待期间依据失效时拒绝提交并保留旧记录。
- 编辑观察明确标记 observation: edit，只计算 HEAD、当前路径状态及路由，不生成完整工作树指纹；该空指纹不是成功收据，也不能用于停止、恢复或用户裁决。完整观察仍用于 SessionStart、Stop、PreCompact 和手动路由。
- 首次差异仍需用户裁决，写入时仍核对所有受保护差异的内容指纹及 HEAD。未知观察、未裁决、只读、路径缺失、范围越界、无效设计和无授权删除仍拒绝写入。会话事实不变不重复提问，策略不表示验证通过。
- 仅编辑观察可复用最近五分钟的成功宿主版本探测；每次检查命令路径及文件身份（真实路径、dev、ino、size、mode、mtime、ctime）。宿主版本缓存仅是路由提示，不是现场加载证据，也不替代写入授权。SessionStart、Stop、PreCompact 和手动路由强制新探测；Stop 重新绑定当前版本并执行最终验证。
- 成功 Stop 收据绑定宿主和已知版本；宿主/版本改变、版本未知、旧收据缺少版本字段均不能复用。已采用基线的写入分支即使无会话标识也必须提供可检查路径；Cursor 已识别的只读工具不受此写入检查影响。
- 语义元数据只在单次校验或 Hook 调用内复用，无引用不读材料，按需扫描找到引用后停止；下一次调用重新读取，不使用持久缓存或仅凭 mtime 复用权威内容。完整校验器仍检查整体结构、重复对象及当前快照。
- 中间只执行最低充分验证，交付前保留仓库要求的 npm test 与 npm run verify，不把性能改进作为取消最终门禁的理由。

## 验收与测量

回归覆盖空引用零读取、单次元数据读取、下一次调用发现变化、任务标识不匹配拒绝、风险不得降级、宿主命令身份/过期失效、编辑观察不读无关差异、完整观察仍绑定内容，以及既有差异裁决、路径和删除保护。

运行 npm run benchmark:preflight -- 7 显式生成临时仓库，对 1000 个语义对象和 16 MiB 未保护差异比较完整/编辑路由的 p50、p95、Git 进程数、读取字节，并测量预检 CLI check。仅输出汇总，结束删除本脚本创建的临时夹具。不读取真实项目内容，不采集提示词、密钥或工具完整输入输出。

此基准不是线上体验或真实宿主证据；首次请求到写入前的助手调查耗时需在采用方主动提供脱敏阶段耗时后单独评估。文件读取和启动成本下降，不等于已证明同事的整体耗时下降。
